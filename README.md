# Oqy — читать и понимать

Прототип для **Órleu Hack 2026, кейс №3 «Образование: читать и понимать»**.
Читательская грамотность для 7–9 классов, работа при слабом интернете. Демо-материалы — 8 класс (2 урока на казахском, 2 на русском).

## Быстрый старт

```bash
npm ci
npm run build && npm run preview   # production-сборка ученика + учителя: http://localhost:4173
npm run server                      # API генерации (Fastify → Ollama) на :8787, нужен для режима учителя
```

Разработка: `npm run dev` (Vite, проксирует `/api` на `:8787`) и `npm run dev:server`.

### Два режима запуска
1. **Публичное демо ученика (статика, без сервера):** https://ughhfu40-collab.github.io/adiadffrvvcv/ — CI публикует его официальным workflow GitHub Pages (`upload-pages-artifact` → `deploy-pages`) после каждого зелёного пуша в `main` и проверяет, что сайт отдаёт `version.json` с SHA этого коммита. В настройках репозитория должно быть: Settings → Pages → Source: **GitHub Actions**. Локально:
   ```bash
   VITE_STUDENT_ONLY=true npm run build   # dist/ можно выложить на GitHub Pages / Netlify / любой хостинг
   ```
   Пути относительные (`base: './'`), PWA кеширует приложение и встроенные уроки — после первой загрузки работает без сети.
2. **Локально с генерацией (учитель):**
   ```bash
   ollama serve
   ollama pull gemma3:12b
   npm run server
   npm run build && npm run preview
   ```

### Выбор модели
Переменные окружения сервера:

| Переменная | По умолчанию | |
|---|---|---|
| `OLLAMA_URL` | `http://127.0.0.1:11434` | адрес Ollama |
| `OLLAMA_MODEL` | `gemma3:12b` | любая модель с поддержкой structured outputs (`llama3.1:8b`, `gemma2:9b`, `aya-expanse:8b` — лучше для казахского) |
| `OLLAMA_TIMEOUT_MS` | `600000` | таймаут генерации (реальные прогоны gemma3:12b на ноутбуке — до 234 с) |
| `PORT` / `HOST` | `8787` / `127.0.0.1` | адрес API |

```bash
OLLAMA_MODEL=aya-expanse:8b npm run server
npm run generate:check        # реальная генерация на одном kk и одном ru тексте
```
Для фронтенда на другом хосте: `VITE_API_URL=http://host:8787 npm run build`.

## Удобство с первого запуска
- **Генерация:** таймер прошедшего времени, кнопка «Отменить» (прерывает и запрос к Ollama), отдельные сообщения об отмене, таймауте и недоступной модели. Черновик и правки учителя при этом не теряются.
- **Качество черновиков:** в промпте есть пример сопоставления, где ответ получается только из двух предложений. Для новых черновиков проверяется: по одному заданию каждого типа, у сопоставления и вывода минимум два разных предложения в каждом наборе. Проблемное задание подсвечивается, урок можно сохранить только после исправления. Старые и импортированные уроки открываются по прежней схеме.
- **Редактор:** доказательства выбираются нажатием на предложения; несколько допустимых наборов — вкладками «Набор 1, 2…», текстовое поле остаётся для опытных.
- **Язык интерфейса:** переключатель қазақша / русский в шапке, выбор запоминается.
- **Импорт с существующим ID:** тот же урок — «ничего не изменено»; другая версия добавляется как `<id>-v2`, существующий урок и прогресс не трогаются.

## Проверки
```bash
npm run typecheck   # TypeScript strict
npm run rubric -- file.json   # автоматическая часть рубрики (формат, ID)
npm test            # Vitest: логика проверки, схема, импорт, IndexedDB, сервер
npm run test:e2e    # Playwright (desktop + mobile): production-сборка, офлайн, импорт, учитель
```
e2e поднимает поддельную Ollama (модель `fake`, отдельные порты 4273/8797/11535 со strict-port — ручной preview на 4173 не будет случайно подхвачен) (`tests/e2e/fake-ollama.ts`) и настоящий Fastify-сервер: проверяются два черновика подряд (поле доказательств и экспорт JSON), ответы модели с `tasks: {}` и `options: null` (ошибка + предыдущий черновик сохраняется) и ошибки только в ID (черновик открывается для исправления).

CI (`.github/workflows/ci.yml`) делает всё это и собирает статическое демо как артефакт.

Порты e2e можно переопределить, чтобы не пересекаться с другими процессами: `E2E_WEB_PORT=4473 E2E_API_PORT=8997 E2E_FAKE_PORT=11735 npx playwright test` (по умолчанию 4273/8797/11535).

Сценарий приёмки на любом адресе (импорт урока учителя → офлайн → перезагрузка → t2 сначала с s3, затем s3+s4 → прогресс 2 из 3 → язык сохраняется), ноутбук 1440 и телефон 390×844:
```bash
node scripts/public-check.mjs http://127.0.0.1:4373/ docs/pitch/lesson-kk-after-teacher.json
```

**Что проверяется автоматически в черновике учителя.** Автоматически проверяются структура урока, ID предложений и вариантов, по одному заданию каждого типа и число предложений в доказательстве. Верен ли ответ и подтверждает ли его цитата — проверяет учитель по тексту. (Эта же формулировка показана в редакторе рядом с шагом «Проверить задания».)

## Редизайн «школьный журнал»
- Палитра: бумага `#F8F5ED`, текст `#202820`, основные действия `#245740`, маркер цитаты `#F5E097`; токены — CSS-переменные со светлой и тёмной схемой (`web/src/index.css`).
- Шрифты Literata (заголовки, текст урока) и Inter (интерфейс) лежат локально (`@fontsource-variable`) и попадают в precache PWA; подмножества cyrillic + cyrillic-ext покрывают ә ғ қ ң ө ұ ү һ і.
- Главная: «Начать урок» одним нажатием открывает задание 1 первого незавершённого урока на языке интерфейса; ниже уроки, затем статистика навыков; импорт — за кнопкой «Добавить урок».
- Урок: на ноутбуке текст и вопрос рядом; на телефоне вопрос сверху, переходы «К тексту» / «К вопросу» не сбрасывают ответ и отмеченные цитаты. После проверки — два отдельных итога: ответ и доказательство; подсказка о недостающем доказательстве зависит от типа задания.
- Учитель: шаги «Вставить текст» → «Проверить задания» → «Сохранить или скачать урок».
- Скриншоты до/после: `docs/redesign/`.

## Как устроено
- `shared/lesson.ts` — **единая Zod-схема урока** (сервер, браузер, импорт JSON) + ссылочная проверка (ID предложений, `correctOptionId`), проверка ответа, отзывы на kk/ru, рекомендации.
- `lessons/*.json` — 4 оригинальных урока; у каждого предложения стабильный ID (`s1…`), задания `find` / `match` / `infer`, несколько допустимых наборов доказательств.
- `web/` — React + Vite + Tailwind, PWA (vite-plugin-pwa/Workbox), Dexie (уроки, попытки, черновик учителя в IndexedDB). Значок «Готово к офлайну» появляется только когда service worker активен и оболочка + бандл с уроками лежат в кеше.
- `server/` — Fastify: `GET /api/health`, `POST /api/generate` (Ollama `/api/chat` с JSON-schema `format`, затем общая валидация), `POST /api/validate`. Если Ollama недоступна — 503 с причиной и командой запуска.

Ответ и доказательство проверяются **отдельно**: при верном ответе и неверной/неполной/избыточной цитате ученик получает конкретную подсказку и повторяет попытку. После урока предлагается задание того же языка по навыку с наибольшим числом ошибок.

## Питч-видео и реальный прогон

[`docs/pitch/oqy-pitch.webm`](docs/pitch/oqy-pitch.webm) — 66 с, записано 27.11.2026 скриптом `scripts/record-pitch.mjs`. Всё в кадре реальное:
1. Учитель вставляет казахский текст, `gemma3:12b` в локальной Ollama генерирует черновик за 209 с. На видео ожидание ускорено ×40, в кадре идёт таймер реального времени.
2. Сервер автоматически проверил формат и ID. Человек сверил t2 с текстом и не засчитал: один факт из s2 вместо сопоставления, а вопрос подсказывает ответ. Учитель переписывает t2 на s3+s4, сохраняет урок и экспортирует JSON.
3. JSON импортируется в публичное демо (GitHub Pages) → «Сеть отключена в Playwright» → перезагрузка → t2 с одной s3 даёт «не хватает доказательства», с s3+s4 засчитывается → после ещё одной перезагрузки прогресс «Выполнено 2 из 3».

Отключение сети подтверждается тем, что запрос мимо кеша падает. Исходный черновик модели, урок после правки и тексты лежат в `docs/pitch/`, оценка всех черновиков — в [`docs/rubric.md`](docs/rubric.md).

## Сценарий защиты (1 минута)
1. *(10 с)* Открываем демо на телефоне → значок «✓ Готово к офлайну». Включаем авиарежим, обновляем — всё работает.
2. *(20 с)* Урок «Возвращение сайгаков»: выбираем верный ответ, но отмечаем не то предложение → «Ответ верный, но цитата его не подтверждает». Исправляем → засчитано. Вопрос-вывод требует двух предложений.
3. *(10 с)* В конце урока — «Ещё одно задание» по навыку с ошибками; прогресс по трём навыкам сохраняется после перезагрузки.
4. *(20 с)* Режим учителя (ноутбук): вставляем текст → видим пронумерованные предложения → «Сгенерировать» → правим черновик → «Экспорт JSON» → импорт в режиме ученика (сломанный JSON отклоняется с понятной ошибкой).

## Библиотеки
React 19, TypeScript (strict), Vite, Tailwind CSS 3, vite-plugin-pwa + Workbox, Dexie + dexie-react-hooks, Zod 4, Fastify 5 + @fastify/cors, Vitest, Playwright, fake-indexeddb, tsx.

## ИИ-инструменты
- **Ollama** (локальная LLM, по умолчанию `gemma3:12b`) — генерация черновиков заданий в продукте.
- **Claude Code (Claude Opus 5.5, Anthropic)** — использовался при разработке: архитектура, код, тексты демо-уроков, тесты. Тексты уроков проверены вручную на соответствие заданиям; казахские тексты рекомендуем дополнительно вычитать носителю языка.
